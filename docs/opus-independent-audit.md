# Opus Independent Audit: Agentic Commerce Zero-Capital Launch Kit

Date: August 8, 2026
Auditor: Claude Opus 4.6 (independent, adversarial review)

---

## Executive Verdict: AMBER

**Strong foundation but material issues remain.**

The project contains genuinely working code, honest documentation for an MVP stage, and commercially plausible positioning. However, prior "production-ready" and "verified" claims overstate the current state. The tool works correctly when it can reach a site, but it fails silently or misleadingly in several common real-world conditions. The MCP server is genuine and functional over stdio. The commercial framing is directionally sound but several claims lack empirical evidence.

---

## What Is Genuinely Working

1. **Track A auditor** -- The Python script runs, accepts URLs, fetches pages, parses robots.txt, checks /products.json, samples product pages, extracts JSON-LD, and produces structured reports. No external dependencies. The scoring model is internally consistent. The outreach copy is carefully hedged. The code handles unreachable sites gracefully with `SKIP OUTREACH`.

2. **Track B MCP server** -- Independently verified. `mcp_stdio_smoke_test.py` successfully launches `server.py` over stdio, initializes an MCP session, lists three tools (`search_books`, `get_work_details`, `explain_wrapper_pattern`), and invokes them with correct JSON responses. The `mcp==2.0.0` SDK with the `mcp-types==2.0.0` companion package is the correct current implementation.

3. **Documentation tone** -- The canonical V2 code has been carefully de-risked. The old aggressive "losing AI traffic" language from the Antigravity V1 is confined to the `archive/` directory. The active outreach copy explicitly says "This does not mean you are losing sales today." The README explicitly disclaims guaranteed rankings.

4. **Research quality** -- The market research report has real, cited sources (Shopify 8x AI traffic, Adobe 1200% growth, McKinsey $3-5T estimate, Gartner cancellation warnings). The ecosystem map is genuinely useful. The layered analysis correctly identifies merchant readiness as the accessible wedge.

## What Is Overstated

### Claim: "Production-ready"
**Reality:** Neither track has been deployed to production. Track A writes files to the current working directory (not configurable). Track B runs only over stdio. No hosting, no authentication, no rate limiting, no monitoring exists. Verdict: **demo-ready, not production-ready**.

### Claim: "Allbirds scored 50/100"
**Reality:** When I ran the audit today, Allbirds returned `score: 0` with "Could not reach homepage." The site blocks the tool's HTTP requests. The historical 50/100 was produced by a different version of the tool (the Antigravity V1 `geo_audit_engine.py`), under different conditions. The current V2 tool has never successfully audited Allbirds. Verdict: **historical result not reproducible with canonical tool**.

### Claim: "Verification Report shows PASS for Track A"
**Reality:** The verification report (August 5, 2026) only ran `--help`. It never actually audited a live site. Running `--help` proves the script compiles; it does not prove it produces correct results. Verdict: **verification was superficial**.

### Claim: Revenue probability estimates (70-75% for first $1k)
**Reality:** These are unsupported subjective estimates generated by AI models. No customer has been contacted. No outreach has been sent. No response rate data exists. Verdict: **speculative, must be labeled as hypotheses**.

## Technical Findings

### Track A: AI Shopping Visibility Auditor

#### Scoring Model (Total: 90 possible, normalized to 100)

| Check | Max | Weight | What it actually measures |
|---|---:|---:|---|
| AI crawler accessibility | 15 | 17% | Whether robots.txt blocks 7 named AI crawlers |
| Machine-readable catalog endpoint | 15 | 17% | Whether /products.json exists (Shopify-specific) |
| Product-page structured data | 25 | 28% | JSON-LD Product schema with price and availability |
| Catalog content completeness | 20 | 22% | Description length, images, variants, tags from /products.json |
| Trust signals | 10 | 11% | Keyword presence on homepage (shipping, returns, etc.) |
| Experimental agent/API manifest | 5 | 6% | Existence of /.well-known/*.json files |

**Assessment:** The scoring model is a reasonable heuristic index of machine-readability. It is NOT a measurement of actual AI shopping visibility (which would require querying AI systems with purchase-intent prompts and checking if the store appears). The name "AI Shopping Visibility Snapshot" is slightly misleading but commercially acceptable if the report includes the existing disclaimer. The more accurate name would be "Machine-Readability Readiness Score."

#### Critical Edge Cases

| Scenario | Behavior | Acceptable? |
|---|---|---|
| Nonexistent domain | Score 0, SKIP OUTREACH | Yes |
| Site blocks requests (Allbirds) | Score 0, SKIP OUTREACH | Yes, but no distinction from unreachable |
| Cloudflare-protected site | Score 0 or partial | Indistinguishable from blocking |
| Non-Shopify store (no /products.json) | Loses 15 points automatically | Problematic -- punishes non-Shopify stores |
| JS-rendered storefronts | Cannot parse JSON-LD | Silent false negative |
| Multiple JSON-LD formats (Microdata, RDFa) | Only checks JSON-LD | Misses valid structured data |
| Paginated catalogs (>20 products) | Only sees first 20 | Sample bias |

#### Security Concerns (Track A)

- **SSRF:** Accepts arbitrary URLs. P1 if deployed as web service. P3 for local CLI.
- **Unbounded downloads:** No max response body size. P1 for hosted. P3 for CLI.
- **Redirect following:** urllib follows redirects silently. P2 for hosted.

### Track B: MCP Server

#### What Works
- Server initializes correctly via Server() constructor
- Tool listing returns correct schemas
- Tool invocation returns correct JSON
- Error handling catches exceptions and returns isError=True responses
- Input validation (empty query, invalid work_key format)

#### What Does Not Work
- client_smoke_test.py has no error handling -- timeout crashes entire test
- No timeout configuration exposed to MCP tool callers
- No retry logic on upstream API failures
